## 2024-05-15 - Interactive custom roles need specific accessibility considerations

**Learning:** When using custom elements (like `div`) with `role="button"`, they do not automatically behave like native `<button>` elements in terms of keyboard interactions. Not preventing default behavior on Space/Enter keydown events can cause the page to scroll unintentionally when the user tries to activate the button via keyboard. Furthermore, visual focus indicators (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`) and dynamically setting the `tabIndex` based on disabled state are necessary to make these components accessible and predictable for screen reader and keyboard-only users.
**Action:** When implementing interactive non-native UI elements, always ensure `e.preventDefault()` is used on Enter and Space key presses in the `onKeyDown` handler to prevent default browser behavior, add visual focus states explicitly (e.g., via Tailwind's `focus-visible` classes), conditionally set `tabIndex`, and add `aria-disabled` if applicable.
