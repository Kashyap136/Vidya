## 2024-05-19 - Internal Input Controls Accessibility
**Learning:** Adding `tabIndex={-1}` to interactive elements inside custom inputs (like the visibility toggle in a password input) completely breaks keyboard navigation for those controls, making them inaccessible to keyboard-only and screen reader users. Also, custom clear buttons inside inputs require explicit `focus-visible` styling and `type="button"` to prevent unintended form submissions, and input fields themselves should handle the `Escape` key to clear content when appropriate.
**Action:** Never use `tabIndex={-1}` on buttons meant for interaction unless specifically managing complex roving tabindex patterns. Ensure all internal interactive elements have explicit focus styling, correct button types, and keyboard shortcut handlers where appropriate.
