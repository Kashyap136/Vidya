## 2024-06-12 - Component File Reading Pitfalls
**Learning:** Tools like `cat` and `read_file` truncate output at 1000 characters. In this Next.js app, UI component files (like `search-bar.tsx` or `password-input.tsx`) often have their critical JSX render functions far below the 1000-character mark. Assuming attributes like `tabIndex={-1}` exist without verifying the actual file structure leads to flawed execution plans and groundedness violations.
**Action:** Always use targeted file reading tools like `tail -n 50 <file>` or `sed -n '30,$p' <file>` to read the end of component files and verify the full JSX structure before proposing changes.

## 2024-06-12 - Dev Artifact Cleanup for Strict Constraints
**Learning:** Running local tests, running Next.js dev server, or even `pnpm install` generates files like `next_output.log`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, and `.env.local`. If these aren't cleaned up before a commit, they get swept into the patch. For strict micro-UX tasks bounded by a 50-line limit, committing thousands of lines of an autogenerated lockfile completely ruins the constraint.
**Action:** Always run `git status` after local verification steps and aggressively clean up (e.g. `rm -f`) any generated logs, lockfiles, or environment files before requesting code review or submitting the final commit.
