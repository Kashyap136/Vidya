
## 2026-08-24 - Prisma Bulk Operations in Pipeline Transactions
**Learning:** In AI generation pipelines (like extraction-pipeline.ts), iterating through AI-generated arrays (e.g., validated topics) and calling repository `create` sequentially inside a transaction loop creates an N+1 query bottleneck. The custom `transaction` wrapper in `@/repositories/transaction` does not automatically provide the repository methods on the `tx` object, so you must interact directly with the Prisma client provided in the transaction callback (e.g., `tx.topic.createMany()`) to perform true transactional bulk operations.
**Action:** When updating generation pipelines to handle bulk insertions, always access the Prisma transaction client passed to the callback directly (e.g., `tx.model.createMany`, `tx.model.deleteMany`) instead of using sequential `create`/`delete` repository method loops, and update corresponding test transaction mocks to expose these `deleteMany`/`createMany` spies.
