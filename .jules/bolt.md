## 2026-08-22 - [Performance] Prisma Bulk Insert Optimization
**Learning:** Sequential `create` operations inside loops in Prisma services (like quiz generation and study plan generation) can cause N+1 query bottlenecks during insertion. While Prisma handles connections efficiently, numerous individual insert statements still incur significant round-trip network overhead. Also, when typing array values for `Json` fields in `createMany`, you must explicitly cast them `as unknown as Prisma.InputJsonValue` to satisfy TypeScript.
**Action:** Always prefer using `createMany` for bulk database insertions instead of sequential `create` operations in loops. Also, when mocking `createMany` inside `$transaction` blocks for Vitest, ensure the specific `model.createMany` is mocked, not just `model.create`.
